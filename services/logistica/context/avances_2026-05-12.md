# Avances Modulo Logistica - 12/05/2026

## Resumen Ejecutivo

Se integro el modulo de Logistica con el modulo de Administracion para consultar y actualizar repartidores reales durante el flujo de aceptacion y finalizacion de entregas.

La integracion se probo contra:

```txt
Logistica: https://modulo-logistica.fly.dev
Administracion: https://pedidosnow-administracion-production.up.railway.app
```

El flujo validado fue:

```txt
Crear entrega en Logistica
Ver entrega en feed disponible
Aceptar entrega con repartidor real de Administracion
Administracion marca repartidor como OCCUPIED
Logistica pasa entrega a asignada
Repartidor marca recogida
Logistica pasa entrega a en_ruta
Repartidor marca entregada
Logistica pasa entrega a entregada
Administracion libera repartidor como AVAILABLE
```

### Aceptacion Desde Feed

Se actualizo:

```txt
src/controllers/feed/feed.controller.js
```

El endpoint:

```http
PATCH /api/logistica/feed/:entrega_id/aceptar
```

Ahora realiza:

```txt
1. Busca la entrega pendiente.
2. Consulta el repartidor en Administracion.
3. Valida que el repartidor este ACTIVE y AVAILABLE.
4. Crea o usa el repartidor local en Logistica.
5. Crea la asignacion local.
6. Cambia la entrega a asignada.
7. Limpia cancelacion_auto_at.
8. Cambia el repartidor local a ocupado.
9. Marca el repartidor como OCCUPIED en Administracion.
10. Registra historial.
11. Notifica cambio de estado al modulo origen.
```

Payload enviado a Administracion al aceptar:

```json
{
  "estado_operativo": "OCCUPIED",
  "modulo_activo": "logistica",
  "entrega_id": 1
}
```

### Liberacion Del Repartidor

Se actualizo:

```txt
src/controllers/entregas/entrega.controller.js
```

Cuando una entrega pasa a estado final:

```txt
entregada

```

Logistica libera la asignacion local, marca el repartidor local como disponible y llama a Administracion:

```json
{
  "estado_operativo": "AVAILABLE"
}
```

## Aclaracion Sobre UI Repartidores

El proceso probado con curl/Postman representa lo que normalmente hace la UI de Repartidores.

Acciones manuales durante la prueba:

```txt
Aceptar pedido
Marcar pedido recogido
Marcar pedido entregado
```

En produccion real esas acciones las dispara el repartidor desde la UI:

```http
PATCH /api/logistica/feed/:entrega_id/aceptar
PATCH /api/logistica/entregas/:entrega_id/recogida
PATCH /api/logistica/entregas/:entrega_id/entregada
```

Logistica automatiza la coordinacion interna:

```txt
Validar repartidor en Administracion.
Crear asignacion.
Cambiar estados.
Registrar historial.
Actualizar estado operativo en Administracion.
Liberar repartidor al finalizar.
Notificar al modulo origen.
```
